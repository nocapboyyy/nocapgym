## Высокий приоритет

### CR-001 — Активная тренировка теряется после перезагрузки WebView

Статус: [x] Выполнено 14 июля 2026 года

Клиент при запуске загружает упражнения, планы и завершенную историю, но не запрашивает активную сессию. Каждый новый старт при этом безусловно создает новую запись в БД. После перезапуска Telegram WebView пользователь не может продолжить тренировку и способен создать несколько активных сессий.

Связанные места:

- [`apps/web/src/App.tsx:411`](apps/web/src/App.tsx#L411)
- [`apps/api/src/routes/sessions.ts:20`](apps/api/src/routes/sessions.ts#L20)

Рекомендуемое решение:

- [x] Добавить пользовательский endpoint получения активной сессии.
- [x] Загружать активную сессию при старте приложения.
- [x] Определить серверную политику: не более одной активной сессии на пользователя.
- [x] При повторном старте возвращать существующую сессию или явно требовать завершить/удалить ее.
- [x] Добавить интеграционные тесты восстановления и межпользовательской изоляции.

Критерии готовности:

- Перезагрузка приложения не теряет текущую тренировку.
- Два быстрых запроса старта не создают две активные сессии.
- Пользователь не может получить активную сессию другого пользователя.

### CR-002 — Импорт backup теряет связь истории с исходными планами

Статус: [-] Отложено 14 июля 2026 года вместе с пользовательским backup flow

Экспорт сохраняет `templateId`, но импорт создает планы с новыми ID и не записывает `templateId` в импортируемые сессии. После восстановления история показывает «План не найден».

Связанные места:

- [`apps/api/src/routes/sessions.ts:182`](apps/api/src/routes/sessions.ts#L182)
- [`apps/api/src/routes/sessions.ts:209`](apps/api/src/routes/sessions.ts#L209)
- [`apps/api/src/routes/sessions.ts:246`](apps/api/src/routes/sessions.ts#L246)

Рекомендуемое решение:

- [ ] Ввести стабильный backup-идентификатор шаблона либо построить соответствие старых и новых ID во время импорта.
- [ ] Восстанавливать `templateId` только через созданную внутри импорта таблицу соответствия.
- [ ] Определить поведение для сессий, чей план отсутствует в backup.
- [ ] Добавить round-trip тест `export → import → export`.

Критерии готовности:

- История после восстановления сохраняет названия и связи с планами.
- Импорт не может привязать сессию к плану другого пользователя.
- Повторный export после import семантически эквивалентен исходному backup.

### CR-003 — Production deployment не применяет миграции

Статус: [x] Выполнено 14 июля 2026 года

В API определена только команда `prisma migrate dev`, а задокументированный production deployment выполняет build и restart без `prisma migrate deploy`. После изменения схемы backend может запуститься на старой БД и падать во время запросов.

Связанные места:

- [`apps/api/package.json:13`](apps/api/package.json#L13)
- [`docs/ai/architecture.md:93`](docs/ai/architecture.md#L93)

Рекомендуемое решение:

- [x] Добавить отдельный script для `prisma migrate deploy`.
- [x] Добавить применение миграций в production runbook до рестарта API.
- [x] Перед миграцией SQLite создавать проверяемую резервную копию БД.
- [x] Описать rollback/recovery procedure для неуспешной миграции.

Критерии готовности:

- Чистая production-like БД разворачивается всеми миграциями одной документированной командой.
- Deployment не запускает новый backend до успешного применения миграций.
- Процедура резервного копирования и восстановления проверена на тестовой копии БД.

Рекомендуемое решение:

- [x] Отклонять timestamps из будущего с допустимым clock skew `60` секунд.
- [x] Возвращать 401 для просроченных и невалидных auth-данных; просроченные данные имеют код `TELEGRAM_AUTH_EXPIRED`.
- [x] Добавить тесты свежего, граничного, просроченного, будущего, отсутствующего и поврежденного `initData`.

## Средний приоритет

### CR-005 — Backend не контролирует жизненный цикл сессии

Статус: [x] Выполнено 14 июля 2026 года

Завершенную сессию можно редактировать, повторный `/complete` меняет `completedAt`, а `/apply-to-template` разрешен до завершения. На клиенте завершение разбито на несколько запросов. Если обновление плана упадет после успешного `/complete`, backend уже считает сессию завершенной, а UI продолжает считать ее активной.

Связанные места:

- [`apps/api/src/routes/sessions.ts:69`](apps/api/src/routes/sessions.ts#L69)
- [`apps/api/src/routes/sessions.ts:102`](apps/api/src/routes/sessions.ts#L102)
- [`apps/api/src/routes/sessions.ts:115`](apps/api/src/routes/sessions.ts#L115)
- [`apps/web/src/App.tsx:536`](apps/web/src/App.tsx#L536)

Рекомендуемое решение:

- [x] Разрешать изменение только активных сессий.
- [x] Сделать завершение идемпотентным или отклонять повторный переход.
- [x] Разрешать применение к плану только для завершенной сессии.
- [x] Рассмотреть один атомарный endpoint завершения с опцией обновления плана.
- [x] Добавить тесты допустимых и запрещенных переходов.

### CR-006 — Backup практически не валидируется перед заменой данных

Статус: [-] Отложено 14 июля 2026 года вместе с пользовательским backup flow

Массивы `templates` и `sessions` принимаются как `z.any()`, а вложенные данные читаются через `any`. Семантически поврежденные, но допустимые для Prisma значения могут быть сохранены. Например, `Boolean("false")` дает `true`.

Связанные места:

- [`apps/api/src/routes/sessions.ts:209`](apps/api/src/routes/sessions.ts#L209)
- [`apps/api/src/routes/sessions.ts:264`](apps/api/src/routes/sessions.ts#L264)

Рекомендуемое решение:

- [ ] Описать полную версионированную Zod-схему backup.
- [ ] Валидировать даты, enums, числа, порядок и обязательные связи до начала транзакции.
- [ ] Не использовать неявное преобразование truthy/falsy для boolean.
- [ ] Добавить ограничения на объем и количество импортируемых сущностей.
- [ ] Возвращать понятный список ошибок без удаления текущих данных.

### CR-007 — Очистка поля повторений создает невалидное состояние

Статус: [x] Выполнено 14 июля 2026 года

Пустая строка преобразуется в `0`, хотя API требует положительное число. При этом `0` снова отображается пустой строкой. Пользователь видит пустое поле, а сохранение или завершение получает 400 без понятного сообщения.

Связанные места:

- [`apps/web/src/App.tsx:230`](apps/web/src/App.tsx#L230)
- [`apps/web/src/App.tsx:1195`](apps/web/src/App.tsx#L1195)
- [`apps/web/src/App.tsx:1412`](apps/web/src/App.tsx#L1412)
- [`apps/api/src/schemas.ts:47`](apps/api/src/schemas.ts#L47)

Рекомендуемое решение:

- [x] Представлять пустое необязательное значение как `null`, а не `0`.
- [x] Не разрешать сохранение плана с нулевыми повторениями.
- [x] Для незавершенных подходов разрешить `actualReps = null`; завершённый подход требует положительные повторы.
- [x] Отображать серверные validation errors в русскоязычном UI.

### CR-008 — Историческое имя плана не является снимком

Статус: [x] Выполнено 14 июля 2026 года

Сессия хранит только nullable-ссылку на живой план с `onDelete: SetNull`. После удаления плана старая история показывает «План не найден», а после переименования отображает новое имя вместо имени на момент тренировки.

Связанные места:

- [`apps/api/prisma/schema.prisma:99`](apps/api/prisma/schema.prisma#L99)
- [`apps/web/src/App.tsx:141`](apps/web/src/App.tsx#L141)

Рекомендуемое решение:

- [x] Добавить в сессию `templateNameSnapshot`.
- [x] Заполнять snapshot при старте тренировки и при импорте.
- [x] Использовать snapshot в истории, сохраняя relation для актуальной навигации.
- [x] Добавить миграцию/backfill для существующей истории, где это возможно.

### CR-009 — Ошибки API раскрывают внутренние сообщения

Статус: [x] Выполнено 14 июля 2026 года

Любая не-Zod ошибка возвращается клиенту как 500 с исходным `error.message`. Ошибки Prisma могут раскрывать внутренние детали схемы. Неверная Telegram-подпись также попадает в этот путь вместо ожидаемого 401.

Связанные места:

- [`apps/api/src/server.ts:37`](apps/api/src/server.ts#L37)
- [`apps/api/src/auth/plugin.ts:18`](apps/api/src/auth/plugin.ts#L18)

Рекомендуемое решение:

- [x] Ввести типизированные HTTP/application errors.
- [x] Отдельно обрабатывать ошибки авторизации, not found, conflict и validation.
- [x] Возвращать клиенту безопасные сообщения, оставляя полную ошибку только в серверном логе.
- [x] Не возвращать stack, Prisma query и внутренние имена таблиц/полей.

### CR-012 — Не хватает индексов для основных выборок

Кроме уникального `User.telegramId`, в Prisma schema нет индексов для частых фильтров по `userId`, `status`, `completedAt`, `exerciseId` и внешним ключам.

- [`apps/api/prisma/schema.prisma`](apps/api/prisma/schema.prisma)

Решение: изучить query patterns и добавить минимальный набор составных индексов, например для истории пользователя и прогресса по упражнению.

### CR-013 — Модальные окна не управляют фокусом

Статус: [x] Выполнено 14 июля 2026 года

Диалоги имеют `role="dialog"`, но при открытии не переводят фокус внутрь, не удерживают его и не возвращают на исходную кнопку.

### CR-014 — Нет статического lint-анализа

Статус: [x] Выполнено 14 июля 2026 года

В workspaces отсутствует lint-script. TypeScript не обнаруживает необработанные Promise в event handlers, проблемы React hooks и часть accessibility-ошибок.

Решение: [x] добавлена flat-конфигурация ESLint для TypeScript/React с проверками floating promises, React Hooks и JSX accessibility; `npm run lint` запускает оба workspace.
